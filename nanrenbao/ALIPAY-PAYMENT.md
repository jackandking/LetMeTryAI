# 男人宝支付宝积分充值接入

## 当前状态

前端充值页已经接入后端订单创建、订单查询和一次性领取契约。后端已实现支付宝 RSA2 签名、异步通知验签和事务式幂等入账；上线前仍需执行数据库迁移并配置服务器环境变量。前端不会根据跳转结果直接增加积分。

## 接口契约

### 创建订单

`POST /payment/alipay/create-order`

请求：

```json
{
  "userUuid": "客户端 PointsSystem 生成的 UUID",
  "packageId": "points_100"
}
```

服务端必须根据服务端套餐配置计算金额，不能信任前端金额，并返回：

```json
{
  "orderNo": "唯一订单号",
  "paymentUrl": "支付宝手机网站支付跳转地址"
}
```

### 支付宝异步通知

`POST /payment/alipay/notify`

服务端必须先验签，再校验 `app_id`、订单号、金额、商户号和交易状态；仅在 `trade_status` 为支付成功状态时，以订单号做幂等入账。重复通知必须返回 `success`，但不能重复增加积分。

### 查询订单

`GET /payment/order/:orderNo`

只返回当前用户可查询的订单状态，不返回私钥、签名原文或内部数据库字段。

## 上线前必须完成

1. 后端使用环境变量保存 `ALIPAY_APP_ID`、应用私钥和支付宝公钥。
2. 异步通知地址必须使用 HTTPS，并且部署在公网可访问的后端服务上。
3. 数据库建立订单表和积分流水表，订单号和支付流水号加唯一约束。
4. 只有异步通知验签成功后才增加积分；前端跳转不能作为入账依据。
5. 支付宝“手机网站支付”审核通过后，再做小额真实支付验证。
